# Kolla-Ansible deploy

Covers `scripts/20-install-kolla.sh` and `scripts/30-deploy-kolla.sh`.

## Install (20-install-kolla.sh)

All Kolla tooling goes into a Python venv at `~/kolla-venv` so it doesn't
fight system Python on Ubuntu 24.04 (which is aggressive about PEP 668
"externally-managed-environment" blocks).

1. `apt install python3-dev python3-venv git libffi-dev gcc libssl-dev`
2. `python3 -m venv ~/kolla-venv && source ~/kolla-venv/bin/activate`
3. `pip install 'ansible-core>=2.16,<2.18'`
4. `pip install git+https://opendev.org/openstack/kolla-ansible@stable/2025.1`
5. `kolla-ansible install-deps` — pulls required Ansible collections
   (`openstack.kolla`, `ansible.posix`, `community.general`, etc.) into
   `~/.ansible/collections/`

The venv is idempotent — re-running the script just re-resolves pip.

## Config scaffolding (30-deploy-kolla.sh, first half)

```
/etc/kolla/
├── globals.yml         ← copied from etc_examples, then our overrides appended
├── passwords.yml       ← generated by kolla-genpwd
└── config/             ← service-specific overrides (we don't need any)
```

Steps the script runs:

1. `sudo mkdir -p /etc/kolla && sudo chown $USER:$USER /etc/kolla`
2. `cp -r $VENV/share/kolla-ansible/etc_examples/kolla/* /etc/kolla/`
3. Append `kolla-config/globals.yml` to `/etc/kolla/globals.yml`
4. `kolla-genpwd` — generates `/etc/kolla/passwords.yml`
5. Copy the `all-in-one` inventory to `~/kolla-venv/inventory`

## Deploy (30-deploy-kolla.sh, second half)

Four Kolla phases, in order:

| Phase             | What it does                                 | Time    |
| ----------------- | -------------------------------------------- | ------- |
| `bootstrap-servers` | apt packages, docker config, /etc/hosts, users | ~5 min  |
| `prechecks`         | sanity: free disk, interface exists, ports free, virt support | ~3 min  |
| `deploy`            | pulls images, starts containers in order    | ~30 min |
| `post-deploy`       | writes `/etc/kolla/admin-openrc.sh`         | ~1 min  |

**If `prechecks` fails, stop and read the error.** The most common failures:

- `neutron_external_interface` doesn't exist — `veth-ext` didn't come up,
  re-run `10-prep-host.sh`
- VG `cinder-volumes` missing — same, re-run `10-prep-host.sh`
- `/etc/kolla/globals.yml` has a typo (YAML is unforgiving — use a colon + space)
- Not enough free disk on `/` — we need >20 GB free after bootstrap

Logs land in `/var/log/kolla/<service>/` inside each container, and in
`~/kolla-ansible.log` for the Ansible run itself.

## Verification after `post-deploy`

```bash
source /etc/kolla/admin-openrc.sh
openstack --insecure service list
# Should show: keystone, nova, neutron, glance, cinder, cinderv3, placement, heat (if enabled)

openstack --insecure endpoint list | wc -l
# ~18+ lines — three endpoints (public/internal/admin) × N services

openstack --insecure hypervisor list
# One entry, state 'up', this host

openstack --insecure volume service list
# cinder-scheduler, cinder-volume, cinder-backup (if enabled); all 'up'
```

## Fixtures (40-fixtures.sh)

Creates the demo objects needed to exercise the three tickets:

- `demo-proj` project
- `alice`, `bob` — users with `member` role in `demo-proj`
- `orphan-charlie` — user with **no** role assignments (for orphan detection)
- `auditor` — user intended to hold a `readonly-auditor` role once it exists

Re-running the script is safe: every command is wrapped so that an
"already exists" error is ignored.
